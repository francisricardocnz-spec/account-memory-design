# 容量与成本：用实际分布代替注册数

> 本页保留概览；深度阅读：[完整成本拆解与敏感性算例](deep-dive/09-capacity-economics.md)。

本文件只有合成算例与公式，不代表某家产品的真实数据、预算、采购计划或已完成负载测试。所有参数都应以实际测量替换。

## 负载

令D为DAU、T为每活跃用户每日轮数、R为每轮记忆服务请求次数、P为峰均比、M为每轮主模型调用次数、S为平均占用秒数：

```text
turns_per_day = D * T
memory_peak_qps = D * T * R / 86400 * P
model_peak_concurrency = D * T * M / 86400 * P * S
```

示例：即使注册账号为1,000万，若DAU为10万、每人8轮、R=1.25、P=10、M=1.1、S=6，约为115.74记忆请求/秒和611.11在途模型请求。不是为千万账号每天调用模型，也不是SQL QPS或供应商保证。

用以下脚本复算示例或替换JSON参数：

```bash
python3 tools/capacity_model.py examples/capacity-scenario.json
```

## 存储

```text
current_items = memory_owners * mean_items_per_owner
logical_bytes = current_items * measured_effective_bytes_per_item
primary_bytes = logical_bytes * history_multiplier * (1 + index_overhead)
modeled_bytes = primary_bytes * (online_copies + backup_equivalent_copies)
```

每条有效记忆的实测字节应分摊Evidence、Claim、修订、边、片段和元数据，不能给每个对象机械乘同一个2KB。多个载体引用同一正文不重计，但权限和删除边界不能为去重而合并。

示例：50万记忆账号、平均40条、每条5KB，逻辑量100GB；历史1.5倍、索引附加70%、3在线+1备份等价值约1.02TB。备份实际压缩/增量要单独量，不能长期沿用倍率。

另计原始附件/媒体、候选区、回执、outbox、日志、导出、WAL、删除登记、首次回填、索引重建双份和余量。向量成本按维度、数值类型、覆盖率、索引与副本单算；与主库账单重叠时去重。

## 模型费用

```text
monthly_cost = SUM(billable_units_by_kind * effective_price_by_kind)
```

分别量当前任务基线、记忆增量、结构化输出、额外抽取/修复、工具续跑、A2A、失败/取消和未知结算。供应商cached/uncached输入、输出、推理等收费项以实际回执和费率版本对账。不用用户可见字数或内部delta字节推导费用节省。

装配缓存可能省DB/CPU，内部Delta可能省传输，供应商缓存只有真实命中才可能降低对应收费。若少输入却多一次模型调用，按总费用判断。脚本不内置供应商费率，避免历史报价被当成当前价格。

## 配额、任务与控制资源

按账号/任务/供应商分层原子预算预留，超时费用未知时不当0元退还后盲重发。后台按版本增量，无变化不重算；闲置账号不每日LLM。

控制面独立保留资源，付费额度耗尽不阻停止/删除。新写未索引积压记录连续水位差和行扫描；高扇出记录根下游分布、批次耗时和屏障覆盖。超界时准确报告不足或暂不可用，不静默漏新更正/反例。

账号配额、每页条数、候选数和token预算是不同限制。配额满应说明占用和管理选项，不能静默删除关键纠正或扩大原保留承诺。

## 规模验收

覆盖空账号、普通账号、10万条极端账号、热点人物/关系、并发纠正删除、冷缓存、索引滞后、N-1、清理积压与供应商限流。按拟发布拓扑测试目标负载和短时突发，测P95/P99、扫描行/返回行、锁/连接池、重建空间、恢复与账单差异。

仅当前输入的降级回答可以算产品可用，但不能算记忆读取成功。SLO、RPO/RTO与清理时限必须绑定实际故障域和可复现证据，不能由设计图直接宣称达标。
