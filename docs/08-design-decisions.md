# 设计问题与取舍

这些取舍使实现分支可解释，不代表所有产品都应采用相同数值。

| 容易含糊的问题 | 设计选择及理由 |
|---|---|
| 新内容失败要不要恢复旧理解 | 纯替代事务回滚；明确否定/停止独立先生效，不能为原子性让错误解释复活 |
| 独立片段会不会逃删 | 独立存储许可与来源谱系分开；仅聊天存储删除可保留已披露片段，整谱系删除必须覆盖 |
| 撤权后如何删除 | 本人管理单独准入，不要求恢复原AI Grant；正文访问仍核保留和敏感规则 |
| 旧记录与新Claim谁为准 | 按合同版本分派，每种记录只有唯一写入权威；旧结构成为投影后不可反向覆盖 |
| confirmed为何仍不能用 | 缺支持、来源、用途或保留时继续待核；UI展示具体缺门，不反复要求认同内容 |
| 设置相互独立是否等于执行完全无关 | 设置值独立，依赖能力受控：读关闭暂停需要历史的整理，总内容写门不阻控制清理 |
| 流式答案最后丢弃是否足够 | 已交付字节不可追回；初始缓冲正文，未来逐段流式另验，不伪称从未发送 |
| 只查最近N条能否做账号记忆 | 只能是窗口，不能代表全账号；按范围有界检索，关键链优先并报告覆盖不足 |
| 索引最大序号能否代表追平 | 乱序可能有洞，用连续已处理水位并合并权威增量 |
| 高扇出删除怎样立即停止 | 根/域控制屏障先阻断，闭包异步批量清理；覆盖不明的投影保守停用 |
| 未知候选和失败队列是否可随便落盘 | 仍是受管正文，需候选保留许可/期限；失败不扩权、不无限续TTL |
| 多字段/多模型是否天然更强 | 先做少字段完整闭环；高级层同预算对照有收益才采用 |

## 默认关闭的扩展

稳定特质、量表测量、发展评级、自动因果确证、生产私人聊天训练、心理画像A2A、模型query改写、多路向量/图融合、主动冷摘要和表达人格引擎，均需各自权利、用途、质量与成本证据。关闭扩展不妨碍用当前输入完成普通任务。

## 版本治理

schema、registry、policy、extractor、prompt、model配置、知识、对象、账号聚合、consent与deletion水位分别版本化。模型升级不能全量无授权重解释旧档案。回退保治理水位，保留真实失败和日期；不把源码存在、配置完成或文档检查当运行验证。
