# 统一术语、冲突与证据口径

本页把多种个人记忆机制重新组织为统一设计判断，不提供原作者、文件名、原件、出处或原报告。以下“原型观察”来自本地静态审阅，不是本仓库的运行验证；读者能检查公开合同与映射，但无法在本仓库回溯被匿名处理的原附件。[公开范围](../PUBLICATION.md)说明这个边界。

## 一、相同名字未必是相同对象

| 常见术语 | 本设计的含义／承接限制 | 不能推出的结论 |
|---|---|---|
| 原话／事实源 | Evidence与SourceBinding保留谁在何时何处说过什么 | 能证明说过，不自动证明客观为真 |
| Memory／事件页／长期页／核心 | 可能分别是事件、检索条目、投影或角色设定 | 都是同一权威对象，可相互覆盖 |
| self／本人 | 真人账号主体、AI角色、叙事视图与工作Agent分别建模 | 角色同意替代真人授权 |
| by／归因／source | 内容归因与受信宿主注入的actor、owner、源版本分开 | 自报字段等于认证身份；历史空值可猜成真人或角色 |
| importance／storage／珍视 | 组织、排序或用户置顶信号 | 永久保留权、事实支持或预算豁免 |
| retrieval／命中／相似度 | 召回、排序与可选反馈信号 | 反复召回增加独立证据，或证明模型已理解 |
| confidence／概率／角色数值 | 先区分来源质量、支持、认识性质与校准概率 | 主观高分变核验；角色情绪变真人量表 |
| wrong／note／conflict／withdraw | 依据具体操作对象识别标错、备注、存疑与撤销更正 | 所有withdraw都等于撤权、删除或数据恢复 |
| archive／软删除／忘记 | 降权、停止检索、归档或可恢复隐藏 | 已物理清理、旧备份不复活 |
| confirmed／active | 内容确认与生命周期为独立轴 | 确认自动补齐Grant、支持和字段开关 |
| seal／健康／测试通过 | 某个观察范围内的结果 | 内容真实、身份认证、授权有效或生产可用 |
| 字符上限／token估算 | 局部趋势指标；硬预算按目标模型最终请求计量 | 一个固定字符系数可证明账单或派发上界 |
| 读到／注入／记住 | 候选、核权读取、装配、派发、接收与有效输出有不同回执 | 一次检索命中就是用户收益 |

## 二、原型间冲突如何处置

| 静态观察到的问题／差异 | 统一设计决定 | 开发时需验证的边界 |
|---|---|---|
| 一类方案永存原文，另一类按周期清理 | 防篡写与保留期限分开；合法删除覆盖内容和派生副本 | 审计不能成为隐藏全文永久备份；删除后摘要、导出和索引不复活 |
| 可撤销归档被命名为“删除” | 用户界面区分暂不使用、撤销更正与删除 | restore或撤销更正不能解除删除屏障 |
| 一个实现将withdraw恢复可见，文档却称停止检索 | 不建立统一字符串直通映射；明确undo_correction、stop_use、delete | 操作前展示对象和影响，按实际状态机回执，不以注释代替行为 |
| 声称仅原文即可重建，但纠正放DB、备份只收原文 | 全部不可重建的控制事件进入受管恢复面 | 干净重建后旧错误不能重新参与检索；无控制登记时能力关闭 |
| 迁移时将作者空值默认归给角色 | 未知保持未知，待核对或隔离 | 不能用猜测清空unknown统计；actor来自受信宿主 |
| 本地锁按年龄删除 | 个人实验可用；多实例以权威版本、lease和fence保护提交 | 锁过期后旧进程继续运行，仍不得写入或重复扣费 |
| 模块任何错误都返回空值，继续回答 | 可选表达模块可降级；来源、Grant、删除和预算控制失败时关闭相关能力 | 不能因角色模块隔离而跳过权限检查，不能回退旧缓存 |
| 角色能自主调参数 | 自主范围由宿主能力、预算、权限与真人控制界定 | 模型不能提高自己的调用／保留／A2A权限 |
| 固定字符容量替代真实token计量 | 字符估算用于趋势；派发前重算最终同装配请求 | 包含工具、媒体、结构输出、输出预留和重试费用 |
| 命中回升与反思洞见增强可信度 | 可试验排序，但不提高独立支持；派生物继承原独立组 | 防自我引用与反馈放大，统计冷门关键反例遗漏 |
| 人物字段全量注册，样例active直接迁移 | 稀疏33目录、21开12关，逐值检查；105概念仅兼容性分析 | 类型、性质、主体、对象、敏感性、当前Grant与支持全部核验 |
| 文档有候选门槛，验证代码没有读取策略文件 | 只有实际接入的代码路径才算执行约束 | 3事件／14天／2情境不是心理学充分条件，也不是已生效保证 |
| 推断active只检查确认，没有检查supported | 主设计增加支持门，确认不提高支持 | confirmed但仅provisional的推断不能长期激活 |
| 7天候选复核被当统一TTL | 新鲜度、复核、保留、Grant到期分别处理 | 到期不恢复更旧画像，候选重试不延长正文保留 |
| 测试报告的范围被外推到生产 | 结构、工程、模型、人工与用户收益分别举证 | 内存校验不证明真实同意、物理删除、DB事务或现实行动 |

这些冲突是采用时的约束，不是给个人原型下生产合格结论。公开版采用独立表述，不包含对应原件或可运行外部软件；具体运行缺陷需要在目标实现上重现。

## 三、状态和数字各有分母

- **认识性质**：reported／observed／inferred／measured／independently_verified，不能通过改标签提升。
- **生命周期**：proposed／active／disputed／superseded／retracted／expired／deleted，描述使用状态，不替代权限。
- **确认**：unasked／confirmed／rejected，绑定精确内容、性质与范围，不自动扩用途。
- **支持**：insufficient／provisional／supported／corroborated，独立组与反证参与判断，重复转述不加组。
- **保存回执**：请求、待确认、待授权、处理中、提交、失败、停止分开；旧内容已停止与替代保存失败可以同时成立。

105是逐项核对的概念数；33／21／12是目标字段总数／初始建议开／关。105行全覆盖不表示105项全采用，更不表示运行适配器已实现。

3份Schema、9接口和27个形状例子属于自编公开工件；另有4个形状可过但运行仍须拦的边界演示。[结果](../examples/contract-check-results.json)只覆盖绑定哈希的结构检查。32组T01–T32仍planned。外部历史测试、库规模、工具数量与对话轮数不公开、不汇总、不作为本项目验收分子。

费用算例用归一化假设，不是真实供应商报价或账单。注册用户数不证明活跃负载、并发、存储或收益。本地13输入／79视图只描述审阅范围，不是公开原件数量或独立实验数。

## 四、变更和发布规则

主合同、字段、Schema、接口、机器示例发现冲突时要同步修订并保留失败记录，不能仅以文档日期决定。匿名分析只提出解释和采用边界，不给模型新增写权限，不开启关闭字段，不改业务代码或生产配置。记忆服务本身仍必须维护合法来源、版本、用途、授权与删除谱系，不能把文档匿名误解为运行时去来源。
