# 五类记忆路线：各自解决什么，为什么组合

本章比较抽象设计路线，不断言任何商业产品的内部实现。个人方案按匿名机制分析；机器合同的技术规范见[规范入口](../09-references.md)。

## 1. 对话历史与压缩摘要

优势是接续自然、实现快，适合单任务上下文。风险是用户原话、AI解释和计划可能一起被压缩；压缩文本不能自然恢复来源真实性、权限和删除语义。

本设计保留有来源的短期接续，但将权威记忆外置。换模型、压缩、暂停恢复或控制变化后，重新核对来源和干净generation；不会因为摘要还在就恢复已撤权内容。

## 2. 个人Markdown与角色内核

可编辑文件适合个人实验、透明检查和人工交接，也便于区分角色设定与工作上下文。多人并发写、逐用途授权、跨实例撤回和规模恢复需要更明确的存储/控制协议。

本设计采用用户可见、可编辑和分层组织的思路；不把整份人格文件常驻所有模型请求，也不把角色情绪当真人证据。Markdown可作导出视图，不作为并发权威库。

## 3. 向量召回与自动抽取

适合按相似语义找到旧内容，减少人工整理。它不能单独解释“某次变化是否替代旧值”“谁允许为哪个用途使用”“这条推断是否足够支持”。

本设计先有owner/用途/时态/生命周期和精确来源门，再按词法/结构化基线评估可选向量。相似分数不当支持等级，embedding也属于可删除的受管派生物。

## 4. 结构化人物与关系模型

可以显式表达视角、情境、时间、反证与修订，帮助长期理解不被一句摘要固化。过多字段也容易诱发默认建档、强行填写未知、心理评分和难以解释的成本。

本设计用稀疏字段白名单：明确自述先行，关闭量表/稳定特质/发展研究等扩展。字段有名称不等于应该给每个用户写一条；完整人物引擎不是普通任务的前置条件。

## 5. Agent工作状态与任务恢复

任务、会话、产物、行动和回执分开，可以避免把模型一轮结束当现实任务完成。反思与方法候选有助于后续执行，但不自动成为用户事实或产品全局规则。

本设计借鉴按需读取、状态显式、有限工具、lease/fence、恢复和幂等；不为了“自主”默认增加多Agent、每轮反思或永久写回权限。持久运行身份不意味着模型持续推理。

## 组合选择表

| 问题 | 首要机制 | 可选优化 | 不采用的捷径 |
|---|---|---|---|
| 换入口重复背景 | 统一身份/用途+有源权威记忆 | 短接续包、稳定装配 | 整份历史永远常驻 |
| 旧事找不到 | 有界结构化/中文词法+权威增量 | 向量/融合/图 | 只看最近N条后说不存在 |
| 一次情绪贴标签 | 性质/支持/范围/确认分离 | 有限假设反证 | 模型高信心即人格结论 |
| 纠正后仍用旧值 | 单一写入权威+最终准入/控制水位 | 通知/取消加速 | 只改卡片或等缓存TTL |
| 删除后恢复复活 | 独立停止登记+恢复先重放 | 拓扑复制与自动重放 | 只有同库Outbox或隐藏全文墓碑 |
| 成本随历史增长 | 稀疏存储、按需读取、增量任务、预算 | 合规真实前缀缓存 | 每账号每日LLM或省字符当省钱 |

## 没有直接照搬的机制

本地JSON权威、无限自动整理、理论目录全量开放、AI角色人格数值驱动、单一万能置信度、无来源推断、未经许可画像A2A和把SDK会话当长期事实库，均不作为默认方案。

取舍应回到同一组问题：用户收益是否可解释、来源和控制是否不变弱、成本是否完整计量、故障是否能恢复、效果是否有独立证据。更复杂不天然更强，更短的提示也不天然总成本更低。
