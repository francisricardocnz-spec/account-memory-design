# 评测：结构正确、回答有用与用户受益分别证明

## 1. 五层证据不能互相替代

| 层 | 回答什么 | 典型证据 | 本仓库状态 |
|---|---|---|---|
| 结构合同 | 类型、枚举、引用形状和上限是否一致 | Schema样例/反例 | 提供结构示例与检查脚本 |
| 工程一致性 | 并发、权限、删除、恢复是否正确 | 数据库/多实例故障试验 | 提供设计与待实施规范 |
| 模型语义 | 是否理解否定、主体、视角与纠正 | 独立真实模型故事集 | 未声称完成 |
| 人工判断 | 依据是否忠实、表达是否恰当 | 盲评/分歧复核与标注规范 | 未声称完成 |
| 用户任务收益 | 是否减少重复、提高帮助而不增加控制负担 | 合法真实试点与任务结果 | 未声称完成 |

本仓库的检查脚本不能测试数据库控制面；Schema拒绝一个错误owner字段也不证明现实鉴权正确。

## 2. 数据集按故事切分

用一组独立故事覆盖首次表达、明确保存、换入口、反例、纠正、停止、删除与重提。不要把同一人物同一故事的多个回合随机分到开发集和留出集，从而把近重复当泛化能力。

合成故事适合系统性覆盖罕见边界；真实试点另核资料、保留、接收方、评测用途和人工访问。去标识化不自动变成匿名，也不自动获得训练/评测许可。

建议故事分层：无记忆、少量自述、长期议题、多人同名、情境变化、否定/讽刺/模拟、时间不明、重度账号、撤回并发、失败恢复。每层报告样本和缺口，不只给一个总分。

## 3. 指标分母

| 指标 | 分子/分母的设计 | 必须单列 |
|---|---|---|
| 接续正确率 | 获准且相关、入口已接故事中正确接续的故事 / 该预定义故事集 | 无权/未接/服务故障不是成功 |
| 错误纳入 | 不该纳入的历史项 / 实际纳入项 | 越权单独严重项，不用平均稀释 |
| 关键召回 | 实际保留的关键事实/反例 / 金标准中当前合法必需项 | 检索命中与最终裁剪后分别报 |
| 纠正适用 | 纠正后实际回答符合新范围的故事 / 预定义纠正故事 | 新文案变色不算语义改变 |
| 控制完成 | 真实阻断/清理声明与操作回读成立 / 控制请求 | 控制故障、部分清理、外部未知 |
| 用户负担 | 同任务重复说明、确认/修正次数、控制耗时 | 不以聊天更长或披露更多为正收益 |
| 成本/延迟 | 总费用或可核成本 / 成功故事；完整分布P95/P99 | 重试/取消/未知、冷缓存/重度账号 |

系统故障后仅用当前输入帮助用户，可以算产品降级可用；不能从记忆调用失败分母中删掉它，也不能当成正确使用历史。

## 4. 四组必要对照

| 对照 | 固定什么 | 问题 |
|---|---|---|
| 无长期记忆 vs 事实记忆 | 同任务、原始输入、模型和预算 | 记忆是否确实减少重复说明 |
| 事实记忆 vs 人物/关系投影 | 同合法来源与最终输入预算 | 复杂层是否有独立收益 |
| 词法基线 vs 可选融合/向量/图 | 候选量、模型、token、权限/停止规则 | 召回收益是否抵消费用与失效成本 |
| 装配/前缀缓存开关 | 相同版本/输入任务，记录真实命中 | 省的是DB、传输还是计费输入 |

移除确认、反证或去重的危险对照只适合获准的离线合成环境，不在真实用户身上关闭保护来追求更高分。

## 5. 人工评审协议

每个输出至少提供当前任务、合法来源/反例、正确范围与实际输出，隐藏候选方案名称。评审者分别判断忠实、必要、情境适用、未观察是否保持未知、控制是否被尊重及表达帮助。

保留分歧而非强迫一致；定义复核流程、严重错误清单和每项依据。模型Judge可作辅助筛查，不能伪造独立人工评审或自动批准敏感用途。

只展示必要材料，不把评审表变成长期私人对话镜像。来源删除/到期后的复评遵循当前保留与授权。

## 6. 统计与真实收益

报告故事级样本量、任务/用户聚类、区间和负面结果；同一运行覆盖多个断言不能冒充多个独立样本。小样本无严重错误不是“已证明零风险”。

用户试点关注实际任务：是否更快得到可用帮助、是否仍需重复说明、能否理解保存/停止状态、错误理解是否更易纠正。关系结束或建议未执行不能自动归为失败，满意也不能证明事实正确。

先预定义指标、样本、退出条件和采用门，再看结果。无收益的复杂层保持关闭，不因已经开发而强行启用。

## 7. 发布门禁

已知跨账号/用途泄露、停止后复活、未确认推断长期使用、伪造来源/核验或旧结果绕过当前水位提交，发现任一应阻断发布。普通语义缺陷和成本超限也有各自出口标准。

产品目标、阈值、人工批准和真实运行分别登记；没有数据就明确未测。不能用文档行数、Schema数量、一次漂亮回答或代码存在代替用户价值证据。
