# 开发合同

## 一次更新的12步

| 步骤 | 工作 | 失败边界 |
|---|---|---|
| 1 接收 | 认证身份、原消息ID、可靠时间和幂等key | 同key不同意图拒绝，不重复收费 |
| 2 准入 | 用途、来源、字段、敏感规则和停止水位 | 不允许提取的资料不转存其他摘要 |
| 3 分主体 | 说话者/被描述者、引用、否定、模拟、假设 | 不凭同名或模型猜测建立跨账号引用 |
| 4 抽取 | 原子Evidence与Claim候选 | 服务端回读原文/坐标，模型quote不是证据本身 |
| 5 对齐 | 事情时间、情境、视角、范围 | 不以worker时间解释昨天 |
| 6 查旧 | 合法旧项、纠正、冲突和反例 | 不从无权库补全 |
| 7 假设 | 任务需要时列支持、替代解释和待核点 | 不把生成的概率当现实概率 |
| 8 提案 | 白名单操作和expected版本 | 拒自由SQL/任意JSON Patch |
| 9 审阅 | 只本轮、候选、内容确认和保存许可 | 不靠赞/已读/普通附和授全部用途 |
| 10 回答 | 完成本任务，分开展示保存状态 | 回答完成不证明记忆提交 |
| 11 提交 | 再核权威状态，Reducer/CAS事务 | 权威修订、依赖、审计、outbox、回执同事务 |
| 12 派生 | 失效/重建投影、索引、缓存与清理 | 延迟不延长旧内容使用权限 |

逻辑12步不等于12次模型调用。可以在一次主调用中返回答复与结构化候选，鉴权、坐标、版本、预算和状态变更由程序完成。

## 写入和并发

写事务核受信owner、Grant、来源和expected版本；外部模型/网络等待不持数据库长事务锁。重试同key回读原操作；旧操作提交后内容已被停用时只返回允许的历史回执及当前状态，不能复活旧正文。

Outbox在业务事务内写入，消费者至少一次投递并按event_id去重、按聚合revision防乱序。缺序列回读权威状态。Outbox不等于独立备份防复活登记。

纯内容替代将旧新版本、边、失效、outbox及回执作为一个事务。用户明确否定或要求停止时，独立控制操作先阻断，替代内容另行提交。若后者失败，返回旧理解已停用/新说明未保存，不回滚停止。

## 读取与上下文

先在owner/用途/范围/状态/时间受限索引内查，再相关排序；精确核权后读取最小正文并交付有限handle。重要纠正、反例和边界有保留优先级，不能被top-k挤掉。

管理列表用稳定keyset cursor，绑定查询/owner/基线/期限，每页重核控制状态。任务相关性搜索与列表分页分开；候选超限返回准确coverage，不把未覆盖当作不存在。

索引与确认提交间用有界权威增量补读。索引连续已处理水位之后的相关合法增量与结果按ID/版本合并，不按最大已见seq跳过乱序空洞。积压超限时走有界回源、等待或说明不足，不读全账号填补。

完整wire计入当前输入、系统/开发指令、工具Schema、媒体、接续文本、历史和输出预留。逐段token作归因，以完整请求计量准入；估算明确标estimated及保守上界，不信客户端token。工具续跑每次重新核权和核剩余预算。

## 派发与交付

停止和派发准入按同一权威控制水位排序。停止之后的新准入拒绝，之前已合法准入的在途请求如实记录并尽力取消；已经发给外部供应商的内容无法远程追回。

初始模式先缓冲历史依赖的答案正文，最终核验与提交通过后交付。将来开放流式答案需另验段间准入、取消和恢复；最终丢弃不能证明之前没有交付字节。

ACK丢失维持dispatch_unknown，查询原operation/provider_request，不换key盲重发。只有当前有效输出提交才推进交付游标；它与记忆保存、外部行动分别有幂等域。

## 独立原话与删除范围

保存独立最小原话前，展示具体片段、用途、保留与删除原聊天的影响，回读原文后建立有独立许可的SourceBinding。保留出处及独立事件组，不靠复制新ID逃避停止。

依赖区分basis_required、independent_support、retention_binding、provenance_origin、display_reference和task_condition。仅原聊天存储删除与整事件/人物/来源谱系删除不同；后者必须覆盖范围内独立片段及派生物。AI解释依赖的其他背景/反例不能因存一小段而被洗掉。

本人管理权与AI处理权分开；AI Grant撤回、读关闭或模型额度耗尽不阻止合法停止/删除。正文和导出仍核当前保留、敏感及第三人限制，已删正文不返回。

## 停止与恢复协议

1. 把幂等停止/删除意图和最小范围写入独立持久登记，取得可恢复序列。
2. 业务事务应用控制水位，拒绝新使用与旧结果提交，记录最小审计及outbox。
3. 只有每个成功停止ACK都被独立持久记录覆盖才提示已停止；物理清理继续分副本推进。
4. 任一步未知保持保守阻断，恢复原operation，不制造另一个分叉删除请求。
5. 旧库/对象/索引恢复先重放最新停止登记再开放业务；登记损坏或缺失时，受影响历史能力失败关闭。

登记不存原文、可重建摘要或可字典反推的短文本裸hash。故障域、备份、保留依据和RPO/RTO要分别设计并演练；单机文件fsync不自动成为云端多节点保障。

## 高扇出与后台任务

先用根/域屏障阻断，再分批求闭包清副本。依赖覆盖不足/超界时停用受影响投影，不能等待worker逐条删除期间继续返回旧摘要。有独立合法支持的内容重算后产生新投影，不自动恢复旧结论。

任务绑定owner/用途、源版本、控制水位、亲本预算、deadline、attempt、lease/fence。无候选保留许可的临时正文不进持久队列、outbox或失败表；队列尽量存受管引用。领取、派发、提交均重核，重试不续TTL。

控制清理有独立保留资源，不能被整理或付费模型额度阻断；同时保留认证、防滥用和公平调度。无变化不重算，闲置账号不常驻模型。

## 有界配置起点

可用于合成合同试验的初值：每次最多32原子项/32来源、3张候选卡、200候选元数据，列表默认20/最多100，在线依赖深度8/节点256、后台批次500、结构修复最多1次。所有值都需按场景冻结并实测，超界拒绝/缩小任务，不截半事务或关键否定。

保留期限、用途/接收方、导出总量、存储配额和预算缺配时关闭相应新能力，不猜无限或永久。已明确的退出操作不能因无关账号版本变化被无限拒绝。
